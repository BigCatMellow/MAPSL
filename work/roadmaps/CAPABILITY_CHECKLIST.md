# Capability evidence checklist

The [master roadmap](00-MASTER-MAPS-CAPABILITY-ROADMAP.md#delivery-order) sets the delivery order. Each group below owns its capabilities. The rows preserve the [original MAPS_Lean checklist at 605ce61](https://github.com/BigCatMellow/MAPS_Lean/blob/605ce610e0be3334d1da7af2a7c6f5912b6cc05f/work/roadmaps/CAPABILITY_CHECKLIST.md), including source-reported status. The current assessment inspected [candidate d535210](https://github.com/BigCatMellow/MAPSL/commit/d5352101c3407b4587674eb99a59e0f6c04de096). See [candidate checks](https://github.com/BigCatMellow/MAPSL/pull/2/checks) and the [disposable operation record](../../migration/operation-evidence.md) for exact revisions and limits.

- **VERIFIED** — evidence meets the scope of this row. Recheck when that path changes.
- **VERIFY** — working code, design or tests exist. Reproduce the stated finish test before accepting.
- **FINISH** — a known implementation, evidence or operating gap has a specific closure step.
- **CONDITIONAL** — retain the evidence and revisit when the stated trigger is met.
- **RETIRED** — preserve the evidence and link the explicit retirement decision.

Run shared work for overlapping IDs once. A source DONE, an exact file copy,
a component test and a live operating result each support a different claim.
Close a row only with evidence at the appropriate level and the applicable
review. A design milestone can pass while the wider operating outcome remains open.
Record confirmed gaps even when the source called the capability DONE.
