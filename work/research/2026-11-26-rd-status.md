# MAPSL research and development status

November 26, 2026 · Draft #2 and the atomic startup update

**MAPSL is an integrated migration candidate with a verified local workflow.**
The draft exercises routing, task claiming, context and run binding, handoff,
lease recovery, exact-run submission and independent-review checks. The
product-level question remains open: how much does MAPSL improve task outcomes
relative to a competent generic workflow, and what overhead does it add?
[Draft and checks](https://github.com/BigCatMellow/MAPSL/pull/2/checks)

## Development

- The preceding candidate completed a disposable coding task and a research
  task using a fresh process per CLI step. Both retained the exact run and
  artifact through review and refused self-review. Its local suite ran 1,515
  tests with five skips and zero failures. All three CI workflows and
  independent technical review passed at the baseline. This evidence covers
  local fixtures and identities. [Operating evidence](../tasks/framework-operating-workflow.md#operating-evidence)
- Startup now commits the claim, run manifest and required environment evidence
  together. Missing environment input can be corrected and retried immediately.
  Fault injection and concurrent-start tests verify that a failed attempt
  leaves no new claim, run or task event, and that a competing or stale
  startup cannot publish over another attempt. The local suite ran 1,520 tests
  with five skips and zero failures. [Startup evidence](../tasks/atomic-flow-start.md#verification)
- The baseline accounted for 3,515 source files and 102 branch references. At
  the atomic startup update, 5 of 80 capability entries had scoped verification,
  40 needed targeted proof, 16 had implementation gaps, and 19 were conditional. These
  are evidence and action categories, so the counts say little about the
  proportion of software finished. [Capability checklist](../roadmaps/CAPABILITY_CHECKLIST.md) · [Migration reconciliation](../../migration/reconciliation.md)
- Draft integration still depends on trusted bootstrap and real default-branch
  protection. The owner makes a separate cutover decision. External target work
  and live provider execution retain their own authority and proof requirements.
  [Current state](../../state/CURRENT.md) · [Successor merge controls](../../docs/CHECKS_AND_BALANCES.md#successor-merge-controls)

## Dependency order

1. With local startup fixed, exercise validation at the actual mutation and
   review boundaries. Prove both recovery success and refusal of an
   incompatible resume. [Framework integrations](../tasks/framework-operating-workflow.md#remaining-framework-integrations)
2. Measure required context and read cost on matched coding and non-coding
   cases. Preserve authority and provenance through handoffs before adding new
   memory or context machinery. [Continuity](https://github.com/BigCatMellow/MAPS_Lean/issues/247) · [Context](https://github.com/BigCatMellow/MAPS_Lean/issues/248)
3. Record the effective harness configuration of the operation actually used.
   Bind it to the run and outcome, then use frozen cases and matched inputs to
   compare reliability, intervention, time and cost. [Learning and evaluation](../roadmaps/CAPABILITY_CHECKLIST.md#learning-and-evaluation)
